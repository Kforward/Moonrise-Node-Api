# 00 后端产品需求文档

## 1. 后端定位

Moonrise 后端用于承接当前小程序的云端数据存储、跨设备同步、备份恢复和数据安全保护。它不是营销后台，也不是医疗诊断系统；第一阶段只服务用户自己的周期数据管理。

## 2. 当前小程序功能映射

- 用户资料：本地资料初始化、昵称、头像、性别、手机号、邮箱、使用天数。
- 周期记录：开始日期、结束日期、流量、痛感、心情标签、备注。
- 周期设置：平均周期、平均经期、提醒开关、提前天数、提醒时间。
- 预测参考：由前端算法根据闭环记录数量和日期区间计算，后端第一阶段只存储基础数据。
- 历史补录：新增、编辑、删除经期记录。
- 数据备份：当前为本地快照；后端需要支持云端快照、历史快照和恢复审计。
- 隐私与安全：当前为本地软件级加密；后端需要为云端同步预留端到端加密、密钥版本、恢复流程。
- 更新日志：后端已提供已发布版本的列表和详情只读接口，前端也可继续保留静态展示作为兜底。

## 3. 第一阶段目标

1. 提供用户身份与设备绑定能力，优先支持微信小程序登录。
2. 支持用户资料、周期设置、周期记录的云端存储与同步。
3. 支持云端备份快照，保留最近 N 次备份。
4. 支持受保护数据的加密元数据记录，不保存明文主密钥。
5. 支持基础审计日志，便于排查同步、恢复和异常访问。

## 4. 暂不实现内容

- 医疗诊断、健康建议自动生成。
- 伴侣联动授权码和只读分享。
- 数字密码锁完整恢复流程。
- 平台安全密钥托管。
- 后端主动推送提醒。

这些能力需要保留扩展点，但不能在文档中写成已完成能力。

## 5. 非功能要求

- 隐私优先：敏感数据最小化采集，支持加密存储与后续端到端加密。
- 可追溯：写操作需有客户端幂等键、版本号或变更日志。
- 可迁移：数据库字段尽量保持业务语义清晰，避免把前端 Pinia 快照原样当作唯一数据模型。
- 可恢复：备份、恢复、密钥版本切换必须有审计记录。
- 前后端分离：接口返回稳定 JSON，不依赖小程序运行环境。
