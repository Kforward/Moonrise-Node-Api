# 06 后端 AI 开发规则

## 1. 默认原则

- 默认使用中文沟通。
- 先读本目录 README，再读 `07_migration_roadmap.md`、`00_backend_prd.md`、`04_database_design.md` 和本文件。
- 每次启动 Codex 时，先根据 `07_migration_roadmap.md` 判断当前任务属于骨架改造、业务模块落地、数据同步、安全隐私还是测试补齐。
- 不把小程序页面状态直接当后端表结构。
- 不把敏感数据当普通业务字段处理。
- 不在业务表中保存明文主密钥、微信 session key 或 refresh token 明文。
- 只设计和实现 `GET`、`POST` 两类 HTTP 请求；更新、删除、恢复等动作统一使用语义化 `POST /xxx/update`、`POST /xxx/delete`、`POST /xxx/restore`。
- 数据库设计默认遵循第三范式，不为前端渲染方便合并不属于同一实体的数据。

## 2. 代码组织

- 新增功能先拆模块：controller / service / repository / dto / tests。
- 模块内部继续分层：domain 负责纯业务规则，service 负责编排，repository 负责持久化，controller 只处理 HTTP 协议转换。
- 底层公共代码放在 `common/`，基础设施适配放在 `infrastructure/`，业务模块不得把通用中间件、加密算法、日志格式散落在各自目录里。
- DTO 必须有运行时校验。
- 数据库写入必须经过 service 层，不在 controller 中直接调用 ORM。
- 业务枚举需要集中管理，前后端枚举值必须保持兼容。
- 日期字段使用明确语义：业务日期用 `date`，事件时间用 `timestamptz`。
- 遵循开闭原则：新增加密算法、认证来源、同步冲突策略、通知渠道时，优先新增适配器或策略实现，不改核心流程。
- 代码必须添加详细的中文注释，重点解释业务意图、关键分支、边界条件和容易误读的处理逻辑。
- 方法、类、工具函数必须添加详细的 JSDoc 描述，至少包含用途、参数、返回值、异常或副作用说明。

## 2.1 中间件使用规则

- 请求日志、请求 ID、认证解析、权限校验、输入校验、幂等处理、限流、错误映射、响应包装等横切能力必须优先使用中间件 / Guard / Interceptor / Hook。
- 业务 service 中不手写重复的 token 解析、响应包装、try-catch 错误映射和限流逻辑。
- 中间件不得记录手机号、邮箱、经期备注、备份快照、密文 payload 等敏感内容。

## 3. 同步与幂等

- 所有写接口必须支持 `clientMutationId`。
- 重复提交同一个 `clientMutationId` 必须返回首次处理结果或幂等成功。
- 任何会影响前端同步的实体都要更新版本或写入变更日志。
- 删除使用软删除。

## 4. 安全开发

- 密码、token、密钥只存哈希或密文。
- 日志中不得输出周期记录、备注、手机号、邮箱和密文 payload。
- 审计日志可以记录资源 ID、动作、结果和哈希化环境信息。
- 错误信息对用户友好，对攻击者不暴露内部细节。

## 5. 测试要求

- 周期记录重叠校验必须有单元测试。
- 幂等写入必须有单元测试。
- 备份创建、恢复审计必须有集成测试。
- 隐私配置切换、密钥版本变更必须有测试。
- API 合约需要有 e2e 测试或契约测试。
