# 05 数据安全设计

## 1. 数据分类

| 类型 | 示例 | 保护等级 |
| --- | --- | --- |
| 身份数据 | openid、设备 ID、token | 高 |
| 个人资料 | 昵称、头像、手机号、邮箱 | 高 |
| 周期数据 | 经期日期、流量、痛感、备注 | 极高 |
| 备份快照 | 用户完整数据快照 | 极高 |
| 展示数据 | 更新日志、配置枚举 | 低 |

## 2. 认证安全

- access token 短期有效。
- refresh token 只保存哈希。
- 每个设备有独立 session。
- 注销设备后对应 refresh token 立即失效。
- 微信 session key 不落库明文。

## 3. 加密策略

### 3.1 第一阶段

- 数据库磁盘加密由基础设施承担。
- 手机号、邮箱、备注、备份快照使用字段级加密或密文列。
- 服务端密钥通过环境变量或 KMS 注入，不写业务表。
- `privacy_configs` 只记录算法、模式和密钥版本。

### 3.2 后续端到端加密

- 客户端生成数据密钥。
- 服务端只保存密文、算法、nonce、key_version、content_hash。
- 忘记密码和设备丢失时不能假装可恢复；必须依赖恢复密钥、可信设备或用户主动备份。

## 4. 审计

必须写入审计日志的操作：

- 登录、刷新 token 失败过多。
- 注销设备。
- 创建、恢复、删除备份。
- 切换隐私加密模式。
- 批量同步失败或冲突。
- 解密失败。

## 5. 风险边界

- 当前小程序本地 AES 属于软件级保护，不等同于硬件级安全。
- 后端第一阶段也不应宣称医疗级合规。
- 后端能增强云端存储安全，但如果采用服务端可解密模式，理论上服务端仍可接触明文。
- 若要最大化隐私，应优先推进端到端加密模式。

## 6. 最小化采集

- 不采集真实姓名，除非后续业务明确需要。
- 手机号和邮箱均为可选字段。
- 不采集地理位置、通讯录、相册等无关权限数据。
- 设备指纹只能保存哈希或随机设备 ID。
